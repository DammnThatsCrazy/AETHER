# Product surface map

**Baseline inspected:** `codex/aether-architecture-reset` at `17503aef9` on 2026-10-04. This is a code-derived map and a proposed migration for the agreed customer navigation: **Snapshot, Graph, Profiles, Journeys, Signals, Lenses, Value, Connectors, Settings**. Aether is the tenant-facing product. Kyber is the private operator control plane. Route presence and a component test do not establish production readiness or an L0–L7 maturity level.

## Customer journey and current Aether routes

The journey is **tenant setup → connect source → see data arrive → see profiles/journeys/graph → apply lens → understand evidence/explanation → take governed action**. The target labels below are placement decisions, not claims that nine complete destinations already exist.

| Target destination / journey step | Actual current route and source | Current evidence and gap | Proposed disposition / owner |
|---|---|---|---|
| Setup and first value | `/` tenant resolver; canonical `/activation` in `pages/activation/activate-page.tsx`; `/activate` alias; `/onboarding` checklist; `/identity/activation` and `/identity/reviews` are flag-dependent tenant identity surfaces. | Activation has goal selection, recommended connect plan, connection statuses, SDK/key/test event and first-value steps. Deep-link parameters are draft preselection, never an automatic save. `/onboarding` reflects an implementation plan and blockers, so it is a distinct companion to guided activation. | Preserve both flows and their APIs. Make the route to first observed value explicit in Snapshot/Connectors copy. Aether activation owner; identity owner for identity surfaces. |
| **Snapshot** | No dedicated `/snapshot` route. `/` currently redirects based on onboarding status; `pages/home/home-page.tsx` is the safe read-only fallback on status read error. Mobile **Today** is a bounded projection, not the web Snapshot. | A single tenant snapshot contract, loading/error/empty/partial semantics, and destination-specific tests are not established by current root behavior. | Add a Snapshot page only from tenant-authoritative status, freshness, and evidence; keep `/` as the activation-aware resolver and preserve deep links. Aether frontend + backend product projection owner. |
| **Graph** | `/explore` is canonical graph workspace; `/graph` redirects to it. `pages/explore/explore-page.tsx` composes `GraphPage`, graph context/time rail, filter builder, lens dock, Noesis handoff, and graph maturity panel. `/clusters/:clusterId`, `/geo[/... ]` are scoped drilldowns. | `app/providers.tsx` gets scope from authenticated profile and resets graph state across scope changes. `GraphPage` supplies loading/empty/error/partial truth and inspector. Lens dock displays registry availability and leaves unknown readiness **not ready**. | Keep `/explore` as a working URL while labeling it **Graph** in nav. | **Profiles** | `/users`, `/users/:id` in `pages/users` and `pages/user-profile`; `/clusters/:clusterId` in cluster 360. | Profile page has overview, journeys, communications, graph, outcomes, identity and other tabs, but a large single component (`user-profile-page.tsx`) mixes many optional dimensions. The dock does not infer backend readiness from its presence. No standalone `/lenses` route or complete cross-surface lens experience exists. | Keep lens controls within Graph first. A standalone **Lenses** destination needs a typed context handoff and evaluated engine/entitlement contract. Shared exploration UI + lens backend owner. |
| **Value** | `/value-review`, `/compare`, `/campaigns/:id` outcome/economic tabs, and related reporting routes. | Value appears in several contexts and measurement truth is modeled in `frontend/shared/src/exploration/truth-model.ts`; no single consolidated Value landing is shown by current router. | Keep existing views. | **Connectors** | `/settings/integrations` shows tenant connection records; `/settings/integrations/connectors` manages connector catalog/config; `/imports[/ :id]`, `/delivery`, and `/settings/sdk-fleet` show ingestion/import/delivery evidence. `/integrations` is an alias. | Connection state is intentionally separate from data readiness. `connectors-page.tsx` maps `never_synced`, permission, revoked, degraded, and other statuses into capability states. Other mounted tenant routes requiring placement decisions include `/campaigns` and `/campaign-intelligence/*`, `/rewards/*`, `/deployments/*`, `/payment-rails`, `/ai-efficiency`, `/stablecoins/*`, `/derivatives/*`, and `/interoperability/*`. Preserve direct access and capability gates while their owner, user demand, data proof, and target-nav fit are reviewed. Do not classify them as archive, experimental, beta, or core from route presence alone.

Route-state infrastructure is in `docs/audits/FRONTEND-ROUTE-STATE-MATRIX.md` and `scripts/validate_frontend_route_state_matrix.py`; `make frontend-route-state` enforces route inventory, at least 90% automated empty-state coverage, and automated empty/error coverage for critical routes. The source table distinguishes automated assertion (`A`), implemented but unasserted (`I`), gap (`—`), and not applicable (`n/a`). Shared state components distinguish failed requests from successful empty responses. Do not erase that distinction when consolidating pages.

**Observed gap and focused closure:** at the unmodified baseline, `/Users/osazehunt/.local/bin/python3.11 scripts/validate_frontend_route_state_matrix.py --json` exited 1 because `/identity/activation` and `/identity/reviews` were absent from the matrix. Reported empty coverage was `133/148` (89.86%) and critical empty/error coverage was `66/66`. In this slice, both routes gained named loading, successful empty, error, capability-off, and populated assertions; the matrix now lists them and `make frontend-route-state` passes at `135/148` empty and `68/68` critical. This closes the inventory/evidence gap, not a product maturity claim. The matrix still marks many other populated and permission states `I` or `—`.

## Evidence gaps and disposition rules

| Question before classifying Core / Beta / Experimental / Archive or L0–L7 | Evidence needed | Current observation |
|---|---|---|
| Which target destinations are functioning products? | Route + typed backend response + capability/permission + populated, empty, failure, partial/stale states + tenant-scoped end-to-end proof | Graph/activation/connectors/profile/journey have mounted components and focused tests; Snapshot, tenant-wide Journeys, unified Signals, standalone Lenses, and consolidated Value lack a demonstrated complete route/contract. Do not assign maturity levels yet. |
| Can the source-to-insight journey be completed on real data? | Credentialed provider or SDK input; arrival/sync timestamps; canonical profile/journey/graph projection; lens result; cited explanation; governed action receipt; tenant isolation | UI paths exist across activation, integrations, imports, Explore, 360s, and actions. This audit did not exercise a provider-backed journey. |
| Which of the many secondary routes should become prominent or archived? | Usage, customer need, backend ownership, entitlement, data truth, support burden, migration impact, and route-state evidence per route | Route count and sidebar placement alone do not decide Core/Beta/Experimental/Archive. Preserve current URLs and gates pending evidence-backed disposition. |
| Do shared 360 panels preserve meaning? | Typed profile/campaign/cluster/geo/operator fixtures; provenance, confidence, value units, freshness, restatement, redaction, and permission tests | Existing panels show these concepts, but the reusable 360 composition API is not yet defined. |
| Does mobile vocabulary change safely? | Device-level navigation, deep links, offline/stale/revoked behavior, accessibility, auth-scope transition, and desktop continuation evidence | Current mobile tabs and state models are code-derived; no device or release proof was run in this audit. |

A local/remote `feat/universal-connector-runtime-blueprint-20261002` branch is visible, while this checkout's Kyber `/provider-connections` and Aether connector routes already exist. Coordinate changes to connector vocabulary, provider state, and identity/360 evidence with those owners; branch presence does not establish a completed or certified runtime. The graph exploration, mobile, and marketing handoff work also has existing tests/contracts to preserve.
