# Runtime authority map

This is an implementation map for the **target** spine: tenant/access → source/intake → immutable evidence → normalization → identity/entity resolution → governed graph mutation and projection → product views/intelligence → explanation → governed action and measured outcome. The L0–L8 labels below describe the proposed target, **not a shipped end-to-end runtime**. The current-code inventory was checked on `codex/aether-architecture-reset` at `17503aef9` on 2026-10-04. [PR #733](https://github.com/DammnThatsCrazy/AETHER/pull/733) was open against `Development` at `7abd1cad8`; its additions are pending integration and are identified separately.

The authority rule across every row is: a source can attest to its own events and objects; Aether alone makes tenant-scoped identity, relationship, causal, journey, value, recommendation, and action decisions. Raw provider IDs, mutable display names, and SDK hints are lineage or candidates, never canonical entity IDs. A delivery receipt proves an external side effect, not a measured outcome or user confirmation.

## Cross-cutting lifecycle and recovery

The target **knowledge state** for a claim is `known`, `unknown`, `inferred`, `conflicting`, `system-confirmed`, `user-confirmed`, or `needs review`. This is a proposed view vocabulary, not an extra runtime enum to add beside `EpistemicStatus` in `services/backend/shared/contracts_models/epistemic.py`. Reuse that existing enum and its provenance-aware mappings where possible; specify the missing user-confirmation and review transitions before implementing an adapter. `OutcomeState` in `services/backend/services/measurement/outcome/contracts.py` instead describes *finality*. A final outcome can still need a separate user attestation. Process state and knowledge state must remain independent.

Target **object processing state** is accepted/recorded → normalized → resolved or review-pending → graph-applied → projection-current → explained/recommended → action-approved/queued/delivered → outcome-observed/confirmed, with explicit rejected, quarantined, failed, dead-lettered, superseded, suppressed and tombstoned branches. The code already has some narrower states: `TemporalDecision` can quarantine/reject (`services/backend/services/ingestion/temporal_enforcement.py`); Bronze records have provenance/quarantine fields (`services/backend/repositories/lake.py`); the outbox relay dead-letters (`services/backend/services/ingestion/outbox_relay.py`); identity stores candidates/conflicts; projection results degrade; delivery jobs dead-letter. These are **not yet one queryable lifecycle**. No downstream stage may silently convert a failed, quarantined, unknown or conflicting object into a successful claim. Retention and erasure are separate governed decisions; quarantined payload is not automatically authorized for indefinite storage.

Replay/backfill must use original L0 evidence, preserve original event/source-revision identity and occurred time, stamp a new delivery/run time, recheck current rights/consent/suppression, then recompute with explicit schema/normalizer/policy versions. Existing `services/backend/services/ingestion/replay.py` is a synchronous, operator-scoped SDK Bronze replay with an in-memory run journal, not a durable resumable job. `services/backend/services/identity/resolution_replay.py` reuses the resolver with a tenant/trigger/policy key; `services/backend/services/projections/projection_restatement_orchestrator.py` has durable tenant-scoped restatement jobs; `services/backend/services/semantic_intelligence/replay.py` is a separate semantic replay. PR #733 adds bounded provider raw replay through the jobs platform, but it is not merged, its `actor_ref`/`decision_ref` are audit references rather than an operator authorization check, and it does not by itself certify a provider-backed graph projection. Backfill must carry a checkpoint, dry-run comparison, failed-row disposition and rollback plan rather than assuming an outbox can serve as a historical log.

The architecture-frame PR does not change `replay_events` or any other
runtime behavior. The existing SDK replay is synchronous and has a process-local
run journal; that does not establish durable recovery, current-rights
re-admission, or exactly-once publishing. Hosted replay safety is not certified
by this inventory. Any restriction or enablement change belongs in a dedicated
runtime slice with focused failure tests and an explicit rollback.

Schema evolution should extend `packages/shared/contracts/event-registry.json`, `observation-envelope-registry.json`, graph mutation taxonomy, identity policies, and the projection/lens registries that already own the corresponding vocabularies. A new source schema or normalizer version must not silently rewrite a source revision or change its logical fact key; preserve both source-native version and Aether interpretation version, with explicit compatibility/upcast or quarantine. Generated twins are integration inputs, not hand-edited source. PR #733's revision-aware provider envelopes and source-object references must be assessed against these authorities after merge.

Operator diagnostics should compose the existing Kyber-only `services/backend/services/ingestion/{replay_routes,observability_routes}.py`, identity explanation/review, graph ledger/checkpoints, projection degradation, delivery receipts/dead letters and provider connection/job evidence into one tenant-filtered trace. `services/backend/main.py` mounts the SDK replay and ingestion observability routes. The trace must answer **which source evidence, policy decision and version led to this claim/action; where did it fail; what may be replayed**. A dashboard count or structural connector certification is insufficient to declare a source, projection or action ready.

## PR #733 integration boundary

At this snapshot, `origin/feat/universal-connector-runtime-blueprint-20261002` is not an ancestor of this worktree. Its diff extends `services/backend/services/provider_runtime/`, `services/backend/shared/integration_contracts/`, `services/backend/repositories/lake.py`, ingestion workers/spine and `main.py`; the architecture reset should rebase/reinspect those exact seams after merge rather than copy a second provider runtime. The PR adds source-revision keys, object-reference and tenant-route primitives, raw-rights admission, canonical Bronze/outbox bridge, provider replay, provider-consumer defer guards and outbox startup checks. Those are **pending code**, not current authority here.

The 2026-10-04 diff also overlaps this reset in generated `docs/REPO-INDEX.md`
and `docs/_generated/doc-manifest.json`, the Aether route-state matrix, and the
two identity route-state tests. The PR tests add query/auth and no-heartbeat
assertions while this reset adds additional explicit empty/loading/error states.
When the connector work lands, regenerate generated docs centrally and merge
the test assertions and route counts; do not take one side's generated or test
files wholesale.

The PR's own rollout notes identify open integration limits: its raw grant lookup is process-memory-backed and fail-closed in staging/production until durable; historical quarantined provider rows lack a re-admission path; `commerce.order.*` has no Silver projector in that slice; the shared bus has no cryptographic producer attestation; graph/Silver parity, provider-backed proof and per-stream certification remain separate. Keep PR #733's source-object ID, source-revision ID and tenant route generation distinct from canonical identity/entity ID and graph mutation ID. Integrate its `EventBridge` with L0/L1 and its connector graph writer only through admitted domain facts and `MutationIntent` under an effective gateway mode. Do not call gateway `off` or connector migration shadow an enforced graph boundary.

## Prioritized change list

**P0**

1. Set the ingress/evidence contract for each source class: authenticated tenant and verified account, rights/consent/minimization, typed rejection/quarantine, original-time and revision identity, and one durable accepted L0/outbox behavior. Resolve SDK V1/V2 divergence and PR #733 bridge overlap with per-tenant parity evidence.
2. Define versioned L0→L1 domain fact and authority decisions. Keep provider-native object status separate from SDK behavioral observation; defer provider consumers until real projectors and tests exist.
3. Prove L1→L2→L3 through the existing resolver and mutation gateway with tenant, evidence, rights, consent, split/restate, replay and enforce-mode ledger/projection parity. Close direct graph-write exceptions only after equivalent behavior is verified.
4. Make failure/quarantine, replay/backfill and operator trace durable and typed across L0–L7. Require a reviewed operator authorization and a scoped checkpoint for provider replay; preserve failed evidence without silently promoting it.
5. Make action approval, idempotent reservation, real provider receipt, measured outcome and user attestation separate linked records. Specify the L8 correction/confirmation authority before any UI labels a claim user-confirmed.

**P1**

1. Adapt remaining 360/mobile composers and recommendation generators to the existing projection and recommendation contracts; compare tenant-visible values and explanation lineage before retiring a parallel path.
2. Add explicit schema/normalizer/policy compatibility and interpretation revisions, plus source revision backfill and field-level conflict handling, using existing registries and generated twins.
3. Build one tenant-filtered Kyber trace across source, replay, identity, graph, lens, action and outcome evidence, with missing/degraded states exposed rather than filled with synthetic success.
