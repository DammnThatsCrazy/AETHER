# Kyber Fraud Investigations Workspace

The Fraud Investigations Workspace in Kyber gives operators a visual environment for exploring fraud networks, tracing money flows, and linking findings to investigation cases.

---

## Navigation

| Route | Purpose |
|---|---|
| `/fraud-networks` | List all detected fraud networks for the current tenant |
| `/fraud-networks/:networkId` | Detail view with graph, members, evidence, case panel |
| `/fraud-networks/flow-trace` | Create and browse flow traces |
| `/fraud-networks/flow-trace/:traceId` | Detail view for a specific trace |

Access requires the `fraud:read` permission. Write actions (build, refresh, escalate, attach) additionally require `fraud:write` or `fraud:escalate`.

---

## Fraud Networks List Page

The list page shows all detected networks with:

- **Label / Type** — human name and fraud category
- **Status badge** — active (yellow), escalated (red), suppressed (green), detected (default)
- **Risk score badge** — color-coded ≥75 red, ≥45 yellow, <45 default
- **Member count** — entities in the network at last refresh

**Filter**: Use the status dropdown to narrow by network status.

**Build Network**: Opens a modal to run fresh detection on a set of anchor entity IDs. Specify network type, optional label, and notes. On submit, the full 8-detector pipeline runs and a new network is persisted.

## Fraud Network Detail Page

### Graph Tab

The graph tab embeds the Cytoscape.js graph canvas showing all network members (nodes) and their connections (edges). Edge types follow the four-layer relationship model:

- `MEMBER_OF_FRAUD_NETWORK` — entity belongs to network
- `LINKED_BY_DEVICE` / `LINKED_BY_IP` / `LINKED_BY_WALLET` — shared-resource links
- `USES_MULE` — orchestrator → mule relationship
- `HAS_CONTROLLER` — delegation control link

**Clicking a node** opens the Entity Node Drawer (slide-out panel on the right).
**Clicking an edge** opens the Edge Drawer.

### Members Tab

DataTable of all network members with entity ID, assigned role, and risk score. Roles are assigned by `classify_member_role()` based on in/out-degree and transfer volume.

### Evidence Tab

The Evidence Tray shows all evidence refs generated by the detection pipeline. Each card shows:

- Signal type badge (colored by severity)
- Source system
- Confidence percentage
- Expandable metadata (e.g., shared device fingerprint, cycle path, etc.)

### Case Tab

The Case Attachment Panel lets operators:

1. **Create a new investigation case** — enters a title, creates the case, and links the network
2. **Attach to existing case** — selects from open cases for the tenant, attaches the network via evidence ref

## Entity Node Drawer

Slide-out panel showing:

- Entity ID, kind, risk score, account age
- Network role (if viewed from a network page)
- Action buttons:
  - **Open Profile 360** — navigates to `/profile360/entity/:id`
  - **Trace Upstream** — pre-fills flow trace form with anchor + upstream direction
  - **Trace Downstream** — pre-fills flow trace form with anchor + downstream direction

---

## Edge Drawer

Slide-out panel showing:

- Edge ID and type
- Source and target entity IDs
- Circular flag
- Transfer details: total amount USD, transfer count
- Risk score badge
- Evidence refs backing this edge

## Flow Trace Page

### Creating a Trace

Fill the trace form:

1. **Anchor Entity ID** — the entity to start from
2. **Direction** — `downstream` (follows money out), `upstream` (follows money in), `both`
3. **Max Hops** — 1–10, platform max configurable via `FLOW_TRACE_MAX_HOPS`
4. **Min Amount USD** — filter out small transfers

Click **Trace** to submit. The BFS traversal runs synchronously and the result appears immediately.

### Reading Results

The result card shows:

- Anchor entity, direction, source count, sink count
- **Cycle Detected** badge (red) if a cycle was found
- The **Flow Trace Paths** component below: each path card shows hop count, pattern tags, total amount, and risk score
- Path node chain rendered as `e1 → e2 → e3` sequence

### Recent Traces

The lower section lists all previous traces for the tenant, clicking navigates to the trace detail URL.

---

## Governance Notes

- Networks and traces are scoped to the tenant that created them; no cross-tenant visibility
- All evidence refs are derived from data already held in the tenant's own transfer, session, and wallet records
- Operator access to another tenant's workspace requires break-glass escalation (see `docs/BREAK-GLASS-ACCESS.md`)
- Suppressed networks remain in the database and can be reinstated; suppression is not deletion
