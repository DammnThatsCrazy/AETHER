# Aether — Economic Value Framing

## Strategic Distinction

Aether does not treat Web2 and Web3 value as separate worlds, and it does not collapse them into one misleading number. It captures economic activity across fiat, Stripe, invoice, on-chain, x402, and internal-credit rails, then maps that activity to the same entity graph. Web3 TVL remains Web3 TVL. Web2 GMV, revenue, and payment volume remain Web2 metrics. Agentic spend and x402 settlement remain agentic commerce metrics. Aether's advantage is that it shows how those values connect across humans, wallets, organizations, agents, campaigns, protocols, and services.

## Why This Matters

Most analytics platforms make one of two mistakes:

1. **Separate worlds** — Web2 analytics tools ignore crypto. Web3 dashboards ignore fiat revenue. Neither sees the full picture.
2. **Misleading collapse** — Some platforms sum everything into a single "TVL" or "volume" number that mixes locked protocol capital with Stripe payments with agent spend, producing a number that is financially meaningless.

Aether avoids both. It preserves each domain's native financial meaning, then normalizes those values into a unified economic graph across entities.

## Metric Taxonomy

### Web3 Metrics

| Metric | Meaning |
|--------|---------|
| **TVL** | Capital locked, supplied, staked, pooled, escrowed, deposited, or otherwise committed inside a Web3 protocol. Only applies to protocol-level entities. |
| **Protocol Exposure** | The value of protocol positions linked to wallets owned, controlled, delegated, or associated with a non-protocol entity (human, org, agent). This is NOT TVL. |
| **Transaction Volume** | Total on-chain transaction value flowing through a protocol or wallet. |
| **Protocol Fees** | Revenue earned by a protocol from its operations. |
| **Rewards** | Tokens distributed as incentives to participants. |

### Web2 Metrics

| Metric | Meaning |
|--------|---------|
| **GMV** | Gross Merchandise Value — total value of goods/services sold. |
| **TPV** | Total Payment Volume — total value processed through payment rails. |
| **Revenue** | Money earned by the business. |
| **Net Revenue** | Revenue after refunds, discounts, and chargebacks. |
| **ARR / MRR** | Annual / Monthly Recurring Revenue for subscription businesses. |
| **AOV** | Average Order Value. |
| **LTV** | Estimated Customer Lifetime Value. |
| **NRR** | Net Revenue Retention — measures expansion vs. churn. |

### Campaign Metrics

| Metric | Meaning |
|--------|---------|
| **Campaign Spend** | Total ad/marketing spend. |
| **Attributed Revenue** | Revenue causally linked to a campaign via attribution. |
| **ROAS** | Return on Ad Spend = attributed_revenue / campaign_spend. |
| **CAC** | Customer Acquisition Cost = campaign_spend / acquired_customers. |
| **LTV** | Predicted lifetime value of acquired customers. |
| **Influenced Protocol Deposits** | Web3 deposits that occurred after campaign touchpoints. Not the same as attributed revenue. |

### Agentic / x402 Metrics

| Metric | Meaning |
|--------|---------|
| **Agent Spend** | Total economic value spent by autonomous agents. |
| **Authorized Budget** | Maximum spend authorized by a human or org principal. |
| **x402 Settlement Value** | Value settled through HTTP 402 payment protocol. |
| **Agent Revenue** | Revenue generated by agent actions. |
| **Agent ROI** | agent_revenue / agent_spend. |

### Unified Metric

| Metric | Meaning |
|--------|---------|
| **Total Value Observed** | All observed economic activity across all domains. Always decomposable — never displayed as a single number without breakdown. |

## TVL vs. GMV vs. TPV vs. Revenue

| | TVL | GMV | TPV | Revenue |
|---|---|---|---|---|
| **Domain** | Web3 | Web2 | Web2 | Web2 |
| **What it measures** | Capital locked in protocols | Total merchandise value | Total payment volume | Money earned |
| **Who it applies to** | Protocols | Marketplaces, e-commerce | Payment processors | Any business |
| **Is it income?** | No | No (includes seller proceeds) | No (includes pass-through) | Yes |
| **Can it be "unlocked"?** | Yes (it's a snapshot) | N/A | N/A | N/A |

These terms are **never interchangeable** in Aether.

## Currency Normalization Rules

1. Native amounts are always preserved alongside any normalized value.
2. USD normalization requires an explicit price source and timestamp.
3. Mixed-currency totals are never presented as a single scalar unless all amounts have USD conversion with provenance.
4. When conversion is missing, warnings are emitted: `MISSING_PRICE`, `STALE_PRICE`.
5. `byCurrency` breakdowns are always available.

## Double-Counting Prevention

In Web3, the same economic value can appear multiple times:
- A user deposits ETH into a lending protocol → receives aToken
- Both the locked ETH and the aToken represent the same underlying value

Aether flags these cases with `POSSIBLE_DOUBLE_COUNT` warnings and, when derivation metadata is available, filters derivative receipt tokens from exposure totals.

## How This Appears in the Product

### Profile360
Every entity (human, wallet, agent, org, campaign, protocol) gets an economic breakdown showing domain-separated metrics connected through the entity graph.

### Tenant Dashboards
Tenant-facing surfaces show Total Value Observed with full decomposition into Web2/Web3/agentic/campaign components.

### Kyber Operator Console
Operators see economic observability including mixed-currency warnings, stale-price alerts, double-counting risks, attribution confidence, and tenant isolation verification.

## Correct UI Copy

✅ **Correct**: Web3 TVL, Protocol Exposure, Total Value Observed, Campaign Spend, Attributed Revenue, Agent Spend, x402 Settlement Value, Web2 Revenue, GMV, TPV

❌ **Incorrect**: Traditional business TVL, Customer TVL, Campaign TVL, Agent TVL, Total TVL across everything

## API Reference

See `packages/shared/economic-metrics.ts` for the canonical TypeScript types.

Key endpoints:
- `GET /v1/profile/{id}/economic` — Unified economic breakdown for any entity
- `GET /v1/profile/{id}/economic/breakdown` — Detailed domain decomposition
- `GET /v1/economic/overview` — Tenant-level economic overview

## Examples

### Example 1: Hybrid Customer

A user has $500 Web2 purchase history, $12,000 wallet protocol exposure, $38 agentic x402 spend, and $1,200 campaign-attributed revenue.

Aether shows:
- Web2 Revenue: $500
- Web3 Protocol Exposure: $12,000
- Agentic Spend: $38
- Campaign Attributed Revenue: $1,200
- Total Value Observed: decomposed, not collapsed into TVL

### Example 2: Protocol

A protocol has 1,000 ETH locked, 2,000,000 USDC locked, $100M transaction volume, and $50k protocol revenue.

Aether shows TVL, Volume, Fees, Revenue, Active wallets, and Campaign-influenced deposits — each as separate metrics.

### Example 3: Campaign

A campaign with $10,000 spend, $45,000 attributed revenue, 200 acquired customers, and 150 wallet connects.

Aether shows:
- Spend: $10,000
- Attributed Revenue: $45,000
- ROAS: 4.5x
- CAC: $50
- Influenced Protocol Deposits: $500,000
- This is **not** "campaign TVL"
