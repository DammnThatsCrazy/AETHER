# How Aether Works
Aether follows a connection-to-perspective loop.
## 1. Connect
Evidence enters through SDKs, connectors, APIs, imports, signed webhooks, and
agent or service observations. A connection is an origin and delivery path; it
is not automatically a verified identity or a complete relationship.
## 2. Normalize and preserve evidence
Incoming observations are classified against canonical contracts. Aether keeps
source, tenant, consent, freshness, provenance, and quality context so that
missing evidence is not mistaken for zero activity.
## 3. Resolve relationships
The platform can connect identities, devices, accounts, organizations, agents,
campaigns, communications, journeys, episodes, and value events when the
available evidence supports that relationship. Confidence and uncertainty remain
visible.
## 4. Create perspectives
Connected relationships become perspectives across the closed loop:
| Relationship | Example perspective |
|---|---|
| Human → human | collaboration, communication, or shared journey context |
| Human → agent | delegation, instruction, recommendation, or approval context |
| Agent → agent | service use, orchestration, dependency, or economic context |
| Agent → human | notification, recommendation, handoff, or escalation context |
## 5. Govern and observe outcomes
Recommendations can be reviewed, actions can require approval, delivery can
produce a receipt, and outcomes can be observed afterward. The loop closes when
the system can show what changed—not when it merely generated another signal.
## Why this matters
Campaigns, SDKs, communications, and connectors are important because they are
ways relationships become observable. The durable value is the connected,
explainable perspective that exists across all of them.
