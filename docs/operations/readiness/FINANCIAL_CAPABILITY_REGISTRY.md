# Financial Capability Registry

> W1 makes the financial capability record a typed, generated contract instead of
> an implicit collection of route, release, and adapter facts.

The credentialless certification matrix already answers what an adapter supports
and how ready it is. The financial capability registry binds that provider fact
to the financial domain it serves and to the release, route, event, rights, and
deployment surfaces that constrain it.

## Canonical records

- **Provider evidence:** `services/api/shared/certification/registry.py` resolves
  each financial adapter's honest `CredentialReadiness` from source.
- **Typed financial record:** `services/api/shared/certification/capability_records.py`
  projects one `FinancialCapabilityRecord` per provider/domain and declares the
  domain surface (release domain, service classification, route prefixes, owner,
  canonical event vocabulary).
- **Generated matrix:** `docs/_generated/financial-capability-matrix.json` is
  generated by `scripts/docs_extract/extract_financial_capability.py`; never edit
  it by hand.
- **Gate:** `scripts/validate_financial_capability_registry.py` cross-checks the
  records against the release manifest, route registry, service classification,
  deployment profiles, data-rights vocabulary, canonical event vocabularies, and
  owner paths.

## Fail-closed rules

- An event type must exist in the domain's canonical vocabulary.
- A required data right must exist in the data-rights authority vocabulary.
- A deployment profile must exist in `config/deployment_profiles.yaml`.
- A production claim requires both an enabled release route and `partner_live`
  readiness. The financial domains are excluded from the current production
  release surface, so every committed record is `staging` only and
  `production_eligible=false`.
- A scaffolded adapter must not advertise event types.
- An advertised event type must be reachable from the adapter's declared
  operations. Snapshot-only derivatives capabilities therefore do not claim
  position lifecycle events.
- A classified route prefix must exist in the route registry; an intentionally
  gated prefix must remain absent from it.
- A financial domain with no records fails the gate.

## Current scope

The first-release financial scope is five domains: payments, stablecoin-chain
observation, derivatives, interoperability, and prediction markets. Provider
counts and readiness states are generated from source in the matrices, not
hand-copied here.

The registry does not promote any provider. It makes unsupported combinations
visible and makes stale route/release/rights/count drift fail before a readiness
claim can ship.
