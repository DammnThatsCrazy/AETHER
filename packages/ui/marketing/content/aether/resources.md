# Aether resources

Aether resources are organized around the questions a team needs to answer before it connects a live source: what the platform understands, how evidence becomes relationship context, how consent and governance apply, and how a team can verify a first result.

## Start with the evidence model

Begin with the connection model, event and consent contract, identity resolution, and the governed loop from evidence to relationship to perspective. The documentation site is the canonical technical reference; this page is the public orientation layer.

## Read the proof honestly

Proof material distinguishes an illustrative scenario, a synthetic demonstration, a partner result, and a measured customer outcome. A capability can be implemented while still requiring credentials, tenant configuration, or a bounded pilot before it is live for a specific organization.

## Follow the release surface

SDKs, connectors, campaigns, communications, imports, webhooks, and agent observations are connection methods into Aether. They are not a substitute for the relationship model. Start with the first question you need answered, connect the smallest useful source set, and expand only when the resulting perspective earns it.
