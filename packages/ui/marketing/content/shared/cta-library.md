# Shared CTA library
Use one primary action per page. The action should match the visitor's next
decision rather than force them to choose a product package before they
understand the relationship question.
## Primary actions
### Start with a relationship question
**Button:** Start a conversation
**Supporting copy:** Tell us what you are trying to understand, which systems
hold the evidence, and what outcome you need to make observable.
### Start an Aether pilot
**Button:** Start a pilot
**Supporting copy:** Bring one concrete question, the sources that contain the
evidence, and the people who can approve the connection and outcome review.
### Open developer documentation
**Button:** Read the developer docs
**Supporting copy:** Choose the connection path you already control, then follow
the contracts for consent, identity, relationships, and outcomes.
### Review trust and procurement
**Button:** Review trust and procurement
**Supporting copy:** Request the deployment-specific architecture, data-flow,
security, availability, and procurement packet.
### Become a proof partner
**Button:** Become a proof partner
**Supporting copy:** Bring a real relationship question. We will help document
the connection-to-perspective loop, and nothing is published without explicit
review and approval.
## CTA routing rules
- Olympus Labs corporate pages route to a company conversation.
- Aether product pages route to a pilot, developer docs, trust review, or proof
  partner conversation.
- A proof CTA must state that participation does not guarantee publication.
- A developer CTA must land on the full developer journey, not only an SDK
  install page.
- A trust CTA must not imply that an unapproved certification, SLA, residency,
  or regulated-workload commitment exists.
