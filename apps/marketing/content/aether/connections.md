# Meet the system where it already lives.
Aether is connected through a suite of paths. The right first connection is the
one that contains the evidence needed for the first relationship question—not
the one with the most impressive integration label.
## First-party application paths
Use the Web, iOS, Android, or React Native SDK when you need application,
session, device, product interaction, or consent-aware identity observations.
The SDK is intentionally thin. It captures the evidence a first-party
application can see and sends it through the approved contract. It does not
pretend to be the entire connection strategy or the entire product.
## Business-system connectors
Commerce, payments, CRM, analytics, support, campaign, communication, and
workflow systems provide context that does not exist inside an application.
Those sources can connect transactions, customer state, touchpoints,
communications, journeys, and outcomes when the deployment provides the
necessary access and context.
## External relationship sources
Social, community, partner, identity, market, and protocol sources can add
relationship evidence when credentials, policy, consent, provider state, and
deployment conditions allow it.
Registry presence does not mean universal availability. A provider is only
available when the current deployment has the credentials, configuration,
contracts, and readiness evidence to use it.
## Direct ingestion paths
Signed webhooks, imports, event APIs, and controlled agent or service
observations cover systems without a dedicated adapter. Direct ingestion still
needs source identity, tenant scope, event time, consent context, provenance,
freshness, and schema version.
## The connection is not the relationship
A connection tells Aether where evidence came from and how it arrived. It does
not automatically prove that a person, campaign, agent, or outcome is what a
source claims.
Aether keeps the path visible, then preserves or resolves relationships only
when the available evidence supports them. The result may be observed,
resolved, inferred, unavailable, or review-required.
## Choose the first path
Start with the source that can answer the first question. Add another path when
it adds context, changes confidence, explains a journey, or makes an outcome
observable.
