# Start with the connection you already control.
The SDK guides are one part of the developer surface. A complete Aether
integration journey includes the connection model, event and consent context,
identity and relationship contracts, API references, security requirements,
readiness state, and outcome verification.
## The recommended path
1. Define the first relationship question.
2. Identify the source system or systems that contain the evidence.
3. Choose the smallest connection path: SDK, connector, webhook, import, API,
   or controlled agent/service observation.
4. Preserve tenant, source, consent, timestamps, provenance, freshness, and
   schema version.
5. Send the first governed observation.
6. Verify identity and relationship states, including missing and conflicting
   evidence.
7. Inspect the resulting perspective and its supporting evidence.
8. Review, approve, deliver, and observe the outcome.
## Connection paths
- Web, iOS, Android, and React Native SDKs for first-party application
  observations.
- Commerce, payment, CRM, analytics, support, campaign, and communication
  connectors for business-system context.
- Signed webhooks, imports, and event APIs for systems without a dedicated
  adapter.
- Controlled agent and service observations for human-agent and agent-agent
  relationship context.
## The SDK is intentionally thin
The SDK captures what the application can observe. It is not the end-all-be-all
of Aether's connectors, and it is not the product identity. The value appears
when SDK observations join other sources and become explainable relationships,
journeys, perspectives, actions, and outcomes.
## Build for evidence, not just delivery
An integration is complete when a team can explain where the evidence came from,
what it supports, what remains uncertain, who can act on the resulting
perspective, and what happened after the action.
